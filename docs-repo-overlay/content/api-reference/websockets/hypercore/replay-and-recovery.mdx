# Replay and recovery

Replay-capable streams deliver incremental updates. Persist the latest cursor after processing a message, then supply it in that subscription's next subscribe frame to request replay. Complete-snapshot streams — `l2Book` and `bbo` — carry no cursor; every message is self-contained, so recovery is a resubscribe.

Resume is per subscription, so subscriptions sharing a connection can resume from different cursors. A replay response indicates whether a gap occurred. When a cursor is invalid or a gap is reported, discard the affected local state and resynchronize from a fresh snapshot before trusting subsequent updates.

Replay depth is bounded by node block-data retention, currently approximately 48 hours. For block-derived streams, gaps that replay cannot bridge can be recovered with the block lookup methods.
