# StreamBlocks

> The contract below is proposed and will be confirmed before general availability.

## What the stream carries

StreamBlocks carries block data for full-chain indexing, action and response analysis, deposit and transfer monitoring, and reconciliation. `round` identifies a block, and `parent_round` links it to its predecessor. See [raw and normalized HyperCore blocks](/docs/chains/hyperliquid/hypercore/concepts/raw-and-normalized-blocks) for the payload structure.

## RPC

`rpc StreamBlocks(StreamBlocksRequest) returns (stream BlockEnvelope);`

The request includes a starting position, an optional cursor, and inclusion controls for commands, actions, events, and fills.

## Message

```proto
message BlockEnvelope {
  string cursor = 1;
  uint64 sequence = 2;
  bool is_final = 3;
  BlockData block = 4;
}
```

## Workflow

Use this as a design pattern: backfill an initial range with `hl_getBlock` or `hl_getBatchBlocks`, consume the live stream, use bounded block lookup to repair a gap, and reconcile against historical lookups when needed. The [JSON-RPC block-method overview](/docs/chains/hyperliquid/hypercore/json-rpc/overview) describes those lookup methods.

Replay depth is bounded by node block-data retention, currently approximately 48 hours. For block-derived streams, gaps that replay cannot bridge can be recovered with the block lookup methods.

## Message size

Raw HyperCore blocks can be large. Clients should configure receive limits and processing queues appropriate to the service limits published at launch.
